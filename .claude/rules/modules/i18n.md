# Internationalization

## When this applies

Apply to every file matching the globs and whenever `PROJECT.md` declares more
than one locale, currency, or user timezone. The default locale, the supported
locale list, the fallback chain, the i18n library, and the translation
management tool are project facts in `PROJECT.md`. Even a single-locale project
follows the date, number, and money rules below; they cost nothing and prevent
the bugs that appear the day a second locale is added.

## Principles

- **Every user-facing string is a key**, never a literal. Code knows keys;
  locale files know words.
- **Formatting is delegated to the platform** (`Intl`, `Temporal`, ICU). Hand
  formatting of a date, number, or currency is a defect.
- **Store canonical, render local.** UTC instants, integer minor units, and
  ISO codes in storage and APIs; locale-specific rendering at the edge.
- **Layout must survive other languages**: longer text, right-to-left scripts,
  different plural systems.
- **Missing translations are build failures**, not runtime fallbacks discovered
  by users.

## Rules

### Keys and messages

| Element | Convention | Example |
|---|---|---|
| Key format | `feature.component.purpose`, dot-separated, camelCase segments | `checkout.summary.totalLabel` |
| Interpolation | named placeholders, never positional | `{count}`, `{name}` |
| Plural / select | ICU MessageFormat | `{count, plural, one {# item} other {# items}}` |
| Rich text | tag placeholders, no HTML in messages | `<link>terms</link>` |
| Reuse | none across features; duplicate the key per feature | `orders.list.emptyTitle`, `invoices.list.emptyTitle` |

- **Never concatenate translated fragments** (`t("hello") + " " + name`). Word
  order differs by language; use one message with placeholders.
- **Never build a key dynamically** (`t("status." + status)`) without an explicit
  map; static analysis must be able to find every key.
- **Every message with a count uses ICU plural**; gender and variant choices use
  ICU `select`. No `if (count === 1)` in code.
- **No HTML inside messages**; use the library's tag or component placeholders.
- **`alt`, `aria-label`, `title`, placeholders, error messages, and email
  subjects are user-facing** and go through keys like everything else.
- **Key names describe purpose, not content**: `checkout.submit.label`, never
  `checkout.placeOrderButton` (the text changes, the purpose does not).

### Locale files

- **One directory per locale, one file per domain**: `locales/<locale>/<domain>.json`
  (or the library's format). A file crossing **500 lines** is split by
  sub-domain (`core/code-standards.mdc` exemption threshold).
- **The default locale file is the source of truth** for keys; other locales
  contain only keys present in the default. CI fails on extra keys.
- **Keys are sorted** and the file is formatted by the project formatter so diffs
  stay minimal.
- **Locale identifiers are BCP 47** (`en`, `fr-CA`, `pt-BR`); the fallback chain
  (`fr-CA` -> `fr` -> default) is declared in `PROJECT.md`.
- **Loading is lazy per locale and per domain**; the client bundle never ships
  every locale.

### Dates and times

- **Store UTC instants** in `timestamptz` / ISO 8601 with `Z`; never local time
  without offset. A "date without time" (birthday, due date) is stored as a
  plain date and never converted through a timezone.
- **Render in the user's timezone**, taken from the profile or the browser and
  declared explicitly on every formatting call (`timeZone: ...`); never rely on
  the server's default zone.
- **Use `Intl.DateTimeFormat`, `Temporal`, or `date-fns-tz` for formatting and
  arithmetic**; never `toLocaleString()` without options, never `Date` string
  parsing, never manual `getHours() + offset`.
- **Recurring and scheduled events keep the source timezone** (`Europe/Paris`),
  not an offset, so DST transitions resolve correctly.
- **DST is a first-class case**: durations use instants, not wall clock; "same
  time tomorrow" is a calendar operation in the user's zone, not `+24h`.
- **Relative times** (`3 minutes ago`) use `Intl.RelativeTimeFormat`.

```ts
const formatter = new Intl.DateTimeFormat(locale, {
  dateStyle: "medium",
  timeStyle: "short",
  timeZone: user.timeZone,
});
return formatter.format(new Date(isoUtc));
```

### Numbers and money

- **Money is an integer amount in minor units plus an ISO 4217 currency code**
  (`{ amount: 1999, currency: "EUR" }`), in storage, APIs, and business logic.
  Floats for money are forbidden; so is a bare number without currency.
- **Minor-unit exponent comes from the currency** (JPY has 0, BHD has 3); never
  assume 2.
- **Rounding is explicit and named** (half-even for accounting totals, per
  `PROJECT.md`), applied once at the end of a calculation, never per line item
  without a documented reason.
- **Format with `Intl.NumberFormat`** (`style: "currency"`, `style: "unit"`,
  `style: "percent"`); never hand-place separators or symbols.
- **Parse locale input with a locale-aware parser**; `1.234,56` and `1,234.56`
  are both valid in some locale. Never `parseFloat` a user-typed amount.

### Layout, text expansion, and RTL

- **UI tolerates +40 % text length** (German, Finnish) and very short text (CJK)
  without truncation or overflow; no fixed-width buttons or single-line labels
  that cannot wrap.
- **Never encode meaning in string length or position** (no "first word is the
  verb" tricks).
- **Logical CSS properties and values only**: `margin-inline-start`,
  `padding-block`, `inset-inline-end`, `text-align: start`. Physical `left` /
  `right` are forbidden outside of directional icons.
- **`dir` is set on `<html>`** from the locale; icons that imply direction
  (arrows, chevrons, "back") flip under RTL; logos and media do not.
- **Sorting uses `Intl.Collator`** with the user's locale (and `numeric: true`
  where applicable); never `localeCompare` without a locale or plain `<`.

### Translation workflow

- **The default locale file in the repository is the source of truth.** The
  translation management tool (see `PROJECT.md`) syncs from it; never edit
  translations only in the tool.
- **New keys ship with the default-locale text in the same PR**; other locales
  may be missing until translated, but CI reports the gap and the release
  checklist blocks on it for supported locales.
- **Machine translation is a draft**: it is marked as such in the file metadata
  and reviewed by a human before the locale is marked supported.
- **Context for translators** is mandatory on ambiguous keys (a `description`
  field or comment: where it appears, max length, what `{name}` is).
- **Unused keys are removed** in the PR that removes the feature.

### SEO and URLs

- **One URL per locale**: path prefix (`/fr/...`) or per-locale domain, declared
  in `PROJECT.md`; never locale by cookie only for indexable pages.
- **`hreflang` alternates on every localized page**, including `x-default`;
  `<html lang>` matches the page locale.
- **Localized metadata**: title, description, Open Graph, and structured data go
  through keys; sitemaps list every locale variant.
- **Locale detection redirects only once**, from the root, based on
  `Accept-Language`; the user's explicit choice persists and wins.

### Tooling

- **i18n library** per `PROJECT.md` (ICU-capable: FormatJS, i18next with the ICU
  plugin, Fluent, or the framework's native solution).
- **Lint**: `eslint-plugin-formatjs` / `eslint-plugin-i18next` (no literal
  strings in JSX, valid ICU), plus a key-usage scanner (for example
  `i18next-parser` or `formatjs extract`) in CI.
- **Pseudo-localization** generator for the `en-XA` style locale.
- **Single check command**: the project's `check` script includes key
  extraction, missing/unused key checks, and ICU syntax validation.

## Testing

- **Missing and unused key tests**: CI extracts keys from code, diffs against the
  default locale (fails on missing) and against usage (fails on unused), and
  checks every supported locale has every key.
- **ICU syntax tests**: every message in every locale parses; plural categories
  present match CLDR for that locale.
- **Pseudo-localization in CI**: a build with the pseudo-locale (accented,
  +40 % length, bracketed) runs the E2E suite; untranslated literals show up as
  plain text and fail an assertion.
- **Snapshot per locale for key screens**: visual regression (Playwright or
  Chromatic) for the pages listed in `PROJECT.md` in every supported locale,
  including at least one RTL locale when supported.
- **Timezone and DST matrix**: unit tests run with `TZ` set to UTC, a negative
  offset, a positive offset, and a zone with DST; cases cover the spring-forward
  gap, the fall-back overlap, and a date exactly at midnight.
- **Currency rounding tests**: property-based (`fast-check`) tests that totals of
  minor units never drift, zero-exponent and three-exponent currencies format
  correctly, and rounding mode matches `PROJECT.md`.
- **Input parsing tests** per supported locale for numbers, dates, and amounts.
- **Collation tests** for sorted lists in at least two locales.
- **RTL visual tests**: layout snapshots with `dir="rtl"`; mirrored icons and
  logical spacing verified.
- **SEO tests**: `hreflang` set, `lang` attribute, and one URL per locale
  asserted in E2E.

## Checklist when touching i18n code

- [ ] No hardcoded user-facing string, including `alt`, `aria-label`, and errors
- [ ] Keys follow `feature.component.purpose`; none built dynamically
- [ ] Counts use ICU plural; gender/variants use ICU select; no concatenation
- [ ] Default-locale text added in the same PR; translator context on ambiguous keys
- [ ] Locale file sorted, under 500 lines, split by domain if needed
- [ ] Dates stored UTC, rendered with an explicit timezone via `Intl` / `Temporal`
- [ ] Money as integer minor units plus currency; rounding explicit and once
- [ ] Logical CSS properties; directional icons flip; `dir` set from locale
- [ ] Sorting via `Intl.Collator`; input parsed locale-aware
- [ ] `hreflang`, `lang`, and per-locale URLs present on indexable pages
- [ ] Missing/unused key check, ICU validation, and pseudo-locale run green
- [ ] Timezone/DST, currency rounding, and RTL snapshot tests updated
