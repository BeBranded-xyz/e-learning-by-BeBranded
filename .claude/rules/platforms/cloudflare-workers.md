# Cloudflare Workers

## When this applies

Apply to every file matching the globs when `PROJECT.md` declares Cloudflare
Workers (including Workers with static assets and Durable Objects). Language
rules live in `languages/typescript.mdc`; function structure, webhooks and
third-party wrappers in `modules/integrations.mdc`; relational rules for D1 or
Hyperdrive-backed Postgres in `modules/database.mdc`. Account id, zone, binding
names and plan tier live in `PROJECT.md`. Limits change; verify against the
platform limits page before relying on a number below.

## Non-negotiables

- **Runtime limits shape the design**: 128 MB memory per isolate; CPU time
  10 ms per request on Free, 30 s default on Paid (raise with `limits.cpu_ms`,
  max 5 min); 50 subrequests per request on Free, 10,000 on Paid; 6 simultaneous
  open outbound connections. Design for them, do not discover them in production.
- **Stream, never buffer, bodies of unknown size.** `await response.text()`
  on an upstream payload is a memory crash waiting to happen.
- **No mutable module-level state that depends on a request.** Isolates are
  reused across requests; a global holding request data leaks or throws
  "Cannot perform I/O on behalf of a different request".
- **Every promise is awaited, returned, or handed to `ctx.waitUntil()`.** Never
  destructure `ctx`.
- **Secrets only via `wrangler secret put`** (or a Secrets Store binding); never
  in `vars`, source, or `wrangler.jsonc`. `.dev.vars` is gitignored.
- **Bindings, not the Cloudflare REST API, from inside a Worker**; service
  bindings, not public URLs, between Workers.
- **Billing traps**: every `fetch` is a subrequest; KV reads and writes, D1 rows
  read and written (a `SELECT *` full scan bills every row), Durable Object
  requests and wall-clock duration, R2 Class A/B operations, Queues operations,
  and Workers AI neurons are all metered. Index D1 queries, cache KV reads,
  batch Queue messages, and never poll a Durable Object.

## Project layout and config files

```
wrangler.jsonc               source of truth: name, main, compatibility, bindings, envs
worker-configuration.d.ts    generated by `wrangler types`; never hand-edited
src/
  index.ts                   default export: fetch / scheduled / queue handlers (thin)
  routes/                    one handler file per route or resource
  durable-objects/<Name>.ts  one class per file, extends DurableObject
  services/ queries/ schemas/ per core/code-standards.mdc
  env.ts                     Env re-export + validated non-binding config
migrations/                  D1 migrations (wrangler d1 migrations create)
test/                        vitest-pool-workers tests, setup, fixtures
.dev.vars .dev.vars.<env>    local secrets, gitignored
```

| Concern | Tool |
|---|---|
| Config | `wrangler.jsonc` (not TOML) with comments explaining each binding |
| Types | `wrangler types` on every config change; CI fails on a stale file |
| Lint | Biome or ESLint with `no-floating-promises` as error |
| Test runner | Vitest + `@cloudflare/vitest-pool-workers` |
| Check command | `pnpm check` = `wrangler types` diff check + typecheck + lint + tests |

Required config baseline:

```jsonc
{
  "name": "my-worker",                      // example
  "main": "src/index.ts",
  "compatibility_date": "2026-09-01",       // pinned; reviewed quarterly
  "compatibility_flags": ["nodejs_compat"],
  "observability": { "enabled": true, "logs": { "head_sampling_rate": 1 } },
  "workers_dev": false,
  "vars": { "LOG_LEVEL": "info" },          // non-secret only
  "env": { "staging": { "vars": { "LOG_LEVEL": "debug" } }, "production": {} }
}
```

- **`compatibility_date` is pinned and bumped deliberately** in its own PR with
  the changelog link; never older than six months.
- Every binding (KV, D1, R2, Durable Objects, Queues, Workflows, AI, Vectorize,
  Hyperdrive, service bindings) is declared per environment with a distinct
  resource id; staging never points at production resources.

## Patterns

### Handlers
- `export default { fetch, scheduled, queue } satisfies ExportedHandler<Env>`;
  each handler wraps the work in try/catch, returns a structured error body with
  a reason code, and logs JSON. Never `ctx.passThroughOnException()`.
- Route with a small router (Hono or `URLPattern`); handlers parse, validate with
  a schema, call a service, respond. Same error-to-status mapping as
  `modules/integrations.mdc`.
- **Post-response work goes to `ctx.waitUntil()`** (analytics, cache writes,
  webhooks); anything longer or retriable goes to a Queue or Workflow.
- Streaming: return `new Response(upstream.body, upstream)` or pipe through a
  `TransformStream`; track the pipeline promise with `ctx.waitUntil`.
- Use `crypto.randomUUID()` / `crypto.getRandomValues()` for ids and tokens and
  `crypto.subtle.timingSafeEqual` on fixed-size digests for secret comparison.

### Durable Objects
- **One object per coordination entity** (room, tenant, document, booking),
  addressed with `getByName(id)`; never one global object.
- **SQLite storage** (`new_sqlite_classes` in `migrations`), schema created in
  the constructor inside `blockConcurrencyWhile`, and nowhere else.
- `extends DurableObject<Env>`, RPC methods instead of `fetch`; access bindings
  through `this.env`, state through `this.ctx.storage`.
- **Persist before you cache in memory**; no `await` between related writes that
  must be atomic. Storage per object is capped (10 GB); shard by entity.
- **One alarm per object** (`setAlarm` replaces); alarm handlers are idempotent
  and reschedule themselves explicitly.
- **WebSockets use the Hibernation API** (`this.ctx.acceptWebSocket`,
  `webSocketMessage` / `webSocketClose` handlers) so idle connections cost
  nothing; attach small tags, never large state, to sockets.

### D1
- **Migrations via `wrangler d1 migrations create` / `apply`** with `--local`
  in dev and CI; production applies from CI on merge. Header and naming per
  `modules/database.mdc`.
- **Prepared statements with bound parameters only** (`.prepare(sql).bind(...)`);
  string concatenation into SQL is forbidden. 100 bound parameters per query.
- **`batch()` for multi-statement writes** (atomic); one round trip, not N.
- Index every filter column; read `meta.rows_read` in tests for hot queries and
  fail when it exceeds the stated budget.

### KV, R2, Queues, cron, AI
| Service | Rules |
|---|---|
| KV | Eventually consistent (reads may lag writes for up to about a minute); 1 write per second per key; values up to 25 MiB. Use for read-heavy config and cache, never as a counter or lock. Set `cacheTtl` on hot reads; store metadata for cheap listing. |
| R2 | Bucket private; browser uploads and downloads through presigned URLs (S3 API with `aws4fetch`) minted server-side after validation; multipart for objects above 100 MB; set `Content-Type` and a content-hash key. |
| Queues | Producer sends with `sendBatch` (max 100 messages, 128 KB each); consumer sets `max_batch_size`, `max_batch_timeout` and `max_retries`, declares a `dead_letter_queue`, processes idempotently, calls `message.ack()` / `retry({ delaySeconds })` per message instead of failing the batch. |
| Cron | `triggers.crons` in config; `scheduled` handler is idempotent, short, and enqueues heavy work; test with `wrangler dev --test-scheduled` and `/__scheduled?cron=...`. |
| Workers AI | Bind `ai`; treat output as untrusted input (schema-validate JSON), enforce per-model token and rate limits, log neuron usage, and never send PII to a model without a documented basis in `PROJECT.md`. |

### Static assets and routing
- **Workers with static assets** (`assets.directory`, `run_worker_first` for
  API paths) for new projects; Pages only where `PROJECT.md` says the site
  already lives there. Production routes in config (`custom_domain: true`).

## Local development and testing

`wrangler dev` runs the Worker locally with Miniflare-backed bindings (`--remote`
only when a binding cannot be emulated, never with production ids). Local D1,
KV and R2 state lives in `.wrangler/` and is gitignored.

| Category | Tool | What it covers |
|---|---|---|
| Unit | Vitest in the Workers pool, import the module directly | services, schemas, routers |
| Integration (bindings) | `@cloudflare/vitest-pool-workers`: `env`, `SELF.fetch()` from `cloudflare:test` | handlers against real local KV, D1, R2, Queues, DOs |
| Durable Objects | `runInDurableObject`, `runDurableObjectAlarm`, `listDurableObjectIds` | storage state, alarms, isolation between ids |
| D1 migrations | `readD1Migrations` in `vitest.config.ts` + `applyD1Migrations` in a setup file | the full chain applies on a fresh DB before every run |
| Queues | `SELF.queue(name, messages)` from `cloudflare:test` | ack, retry, DLQ paths |
| Contract | recorded fixtures | webhook payloads and signatures |
| E2E | Playwright or HTTP tests against a preview URL or `--env staging` | critical journeys with real routing and TLS |
| Load | k6 against staging | CPU-time headroom, subrequest counts, DO hot keys |

```ts
// vitest.config.ts
import { defineWorkersConfig, readD1Migrations } from "@cloudflare/vitest-pool-workers/config";
import path from "node:path";

export default defineWorkersConfig(async () => ({
  test: {
    setupFiles: ["./test/apply-migrations.ts"],
    poolOptions: {
      workers: {
        wrangler: { configPath: "./wrangler.jsonc" },
        miniflare: { bindings: { TEST_MIGRATIONS: await readD1Migrations(path.join(import.meta.dirname, "migrations")) } },
      },
    },
  },
}));
```

- Every KV `get` returning `null`, every Queue retry path and every DO alarm has
  a test. Isolated storage per test is the default; do not share state.

## Deployment and environments

- **Environments are `env.staging` and `env.production` blocks** in
  `wrangler.jsonc`; `wrangler deploy --env <name>` from CI only. Top-level config
  is the local dev default, never a deploy target.
- **Secrets per environment**: `wrangler secret put NAME --env production` from
  CI secrets; `wrangler secret list` diffed against `.env.example` in CI.
- **Preview per PR**: `wrangler versions upload` gives a preview URL for review
  and E2E; `wrangler versions deploy` with a percentage for gradual rollout of
  risky changes; roll back with `wrangler rollback`.
- Durable Object renames or deletions go through `migrations` entries; D1
  migrations apply in CI before the Worker deploys and block it on failure.

## Observability on this platform

- `observability.enabled: true` with `head_sampling_rate` tuned per env; traces
  enabled where the plan allows. Logs are JSON objects with `request_id`, route,
  status, duration and ids only; `console.error` for errors.
- `wrangler tail --env <name>` for live debugging; Logpush for retention;
  `@sentry/cloudflare` (`withSentry`) with the release set from CI.
- Alerts on error rate, CPU-time p99 approaching the limit, Queue backlog and
  DLQ size, D1 rows read per request, and subrequest exhaustion.

## Checklist when touching Workers code

- [ ] `wrangler.jsonc` updated; `wrangler types` regenerated; no hand-written `Env`
- [ ] `compatibility_date` pinned; `nodejs_compat` present; observability enabled
- [ ] No secret in config or source; `.dev.vars` gitignored; `wrangler secret` per env
- [ ] Bodies streamed; no unbounded `text()` / `arrayBuffer()`
- [ ] No request-scoped module state; every promise awaited or in `ctx.waitUntil`
- [ ] Bindings used instead of REST API; service bindings between Workers
- [ ] Durable Object: one per entity, SQLite storage, idempotent alarm, hibernating WebSockets
- [ ] D1: migration file, bound parameters, batch writes, indexed filters
- [ ] Queues: batched sends, per-message ack/retry, DLQ declared; cron idempotent
- [ ] Tests in the Workers pool cover bindings, DO state, migrations, retry paths
- [ ] Staging and production envs point at separate resources; deploy from CI only
- [ ] Cost impact stated in the PR (subrequests, KV/D1 ops, DO duration)
